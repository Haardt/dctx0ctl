# Complete acceptance from the Rust CLI

The complete Cinema acceptance no longer needs Python:

```sh
cargo build -p dctx0-cli --all-features
target/debug/dctx0 verify complete examples/cinema/dctx0 --project examples/cinema
```

With an installed binary, use `dctx0 verify complete` with the same arguments.
Bun must be available and Cinema dependencies installed (`bun install
--frozen-lockfile --cwd examples/cinema`). Production execution remains native
TypeScript; the CLI, orchestration and assessment are Rust.

The command explicitly checks the spec, creates missing TypeScript profile files
while preserving existing ones, publishes a current task plan, executes the
configured verification scope, binds authored program inspections, and delivers
eligible inspected tasks through the existing guarded transactions. It requires
a nonempty active plan with every task Done/PASS. Running or reserved work,
historical Done without PASS, incomplete native cases, actual failures and
missing inspections prevent complete acceptance. Earlier successful phases and
native evidence remain recorded when a later phase fails; code is never rolled
back. Existing task definitions and historical results are retained.

By default the command reads
`.dctx0/testing/typescript/inspection-notes.json` under the application root.
`--inspections <file>` selects another authored notes file. These are existing
human/agent judgements, not approvals generated by this command. Each reviewed
source's SHA-256 must match before and after execution. Every spec source also
needs a reviewed hash: use its application-relative name in `reviewed_hashes`,
or a spec-root-relative entry in `reviewed_spec_hashes` when the spec lives
outside the application root. Changed sources or newly discovered spec files
require renewed substantive inspection before their hashes are updated.

Notes schema 1 contains `actor`, `scope`, `reviewed_hashes`, optional
`reviewed_spec_hashes`, and a `subjects` map. Each subject supplies `report`,
`limitations`, and an optional review (`approved`, structured `findings`). Native
FAIL cannot be replaced by an authored approval. The Rust assessment resolves
suite/review/policy requirements; missing judgements remain UNKNOWN. Automatic
and effective results are shown separately.

Use `--json` for a compact machine-readable completion report. The original
native observations and effective inspection report remain immutable in SQLite.
The summary is additionally saved as
`<spec-root>/.dctx0ctl/verification-complete/<native-run-id>.json`.

On Linux, when a systemd user manager is reachable, the CLI re-executes itself in one
scope with `MemoryMax` set to two thirds of current `MemAvailable` and swap
disabled. Set `DCTX0_MEMORY_GUARD=0` to disable this optional cap. On other
platforms or without the required systemd tools/user manager, the CLI continues
without a collective RAM cap and prints an explicit message.
This cap covers the CLI and native descendants together. Failure to
create the scope stops the command rather than silently executing without a
limit. This is resource control, not a security sandbox. This first complete
runner supports TypeScript/Bun on Linux; other targets retain their separate
capability boundaries.

Repeated planning within the same check occurrence remains idempotent. A fresh
successful check of identical requirements publishes a new immutable plan
binding to that occurrence, retaining task IDs, definitions, states and earlier
plans. This allows repeated native acceptance without treating the current
plan as historical.

Release performance and workspace development checks remain separate from
product acceptance. They are not prerequisites for invoking this Rust command.

## Go target

The same command selects Go when the project's verification configuration names
`go`. Its default notes path is `.dctx0/testing/go/inspection-notes.json`.

```sh
go mod download -C examples/cinema-go
dctx0 verify complete examples/cinema-go/dctx0 --project examples/cinema-go
```

Go is compiled once in a managed build, then the actual worker binary executes
the shared Rust plan. Compiler inputs and the binary receive separate provenance;
there is no Go implementation of expectations or case generation. See
[Go target behavior and boundaries](go-target.md).

## Rust target

The same command selects Rust when verification.json names target `rust` and
runtime `cargo`. Its authored notes live under `.dctx0/testing/rust`. Prepare
the adapter package's committed Cargo.lock dependencies before offline native
execution. See [Rust target behavior and boundaries](rust-target.md).

## Persisted task-review workflow (2026-10-12)

The complete runner also consumes source-bound reports recorded through normal
Review tasks. Inspection notes are now optional when current task reports supply
the required authored evidence. These reports bind the complete application
inventory, spec source hash, snapshot, task requirements and assigned subjects.
A later rejection or stale task binding cannot be masked by imported notes.

Fresh Cinema plans now contain 105 tasks and four Review tasks responsible for
all 25 manual/suite/policy obligations. Review completion does not set testing
PASS: `reviewed_tasks` is separate, and `non_pass_tasks` includes Done/Unverified
reviews. Historical 104-task acceptance records above remain unchanged. Only
non-review tasks require testing PASS for complete acceptance; every reviewed
obligation and modeled release gate must still be satisfied. Read
[agent conformance reviews](conformance-reviews.md) for commands, renewal and limits.
